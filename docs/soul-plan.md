## 2. 拆解：把「灵魂」换成四件能验收的事

【推断】以下四条是从现在的代码结构反推的，不是当时的原话次序。

### 支柱一：连续的自我（记忆）

要能说「上次聊到哪儿」，就必须有跨会话的、能查证的、会过期的记忆。

- 三段式：投递 → 待审缓冲区（不生效）→ 用户裁决 → 才进提示词。链路见 `README.md:162-176`。
- 为什么不做静默自动写入：写错了用户很难发现，而记忆一旦静默生效就会污染之后所有回答。原文见 `README.md:175-176`。
- 每条记忆带四个字段：`type` / `state` / `verifyAt` / `sourceRef`，缺了它们用户只能整份相信记忆库。见 `README.md:185-198`。
- 时间衰减按类型分窗：`preference` 540 天、`stance` 365 天、`event` 180 天、`fact` 不衰减。见 `lib/decay.mjs:50-52`。

### 支柱二：诚实（回答质检层）

要能不糊弄你，就得让「没查」和「查了没事」长得不一样。

- 十二条判据 R01–R12，其中 **R03 / R05 / R06 / R07 / R10 这五条明写「机器永远判不了」**，每次出判词都要附「这五条没查」。见 `README.md:241-260`，实现见 `lib/quality.mjs`。
- 对账三档机械触发：数字/日期/比例、自查类断言、归属类引用。见 `README.md:262-282`。
- 代码不判内容对错，只判形状 —— 判内容这件事代码永远做不到。见 `README.md:233-239`。

### 支柱三：主动，但克制（巡夜）

要能主动说话，但不能变成噪音源。

- 每晚到点跑一次，判据只有三样机器数得出来的：待审集合变没变、体检 flagged 集合变没变、这次整理有没有真动数据。见 `lib/patrol.mjs`，`README.md:358-372`。
- 用「集合变没变」而不是「数量 > 0」：三条候选挂一周没人管，每天报一遍是纯噪音。见 `README.md:371-372`。
- 沉默必须能反查 —— 否则「巡过了没事」和「根本没跑」长得一模一样。见 `README.md:374-377`。

### 支柱四：可见、可关

- 设置页能看到每条记忆为什么进、为什么没进；能逐条采纳/丢弃/删除。
- 质检卡片在 `checks === 0` 时直接写「这一整套没在工作」，**不许显示得像一切正常**。见 `README.md:342-356`。

## 3. 验收标准：机器能判的才算

这个方案能立住，靠的是每条都能当场跑出来，而不是我说它好。

【事实】核心用例现在能跑通：


四条支柱各自的验收动作：

- **记忆**：`/anima checkup`（`POST /api/anima/memory/audit`）。它只验两件机器验得了的事 —— 记忆里的 Windows 路径还在不在、`verifyAt` 过没过期。它**不判断新记忆有没有推翻旧的**，因为那是语义判断，一自动做就会生成你没说过的话。见 `README.md:210-219`。

- **主动**：手动跑巡夜和定时跑巡夜必须走同一条判据 —— 如果手动能绕过，就永远测不到定时那次的真实行为。见 `README.md:360-363`。

## 4. 反目标：这些是刻意不做的

比「做了什么」更能说明这个方案的立场：

- 不声称自己「通过了十二条」。R03 / R05 / R06 / R07 / R10 只有人能判，代码自称通过就是撒谎。
- 不把提醒当纠错机制。它的真实作用是**留痕**，不是把下一条改对（见第 5 节数据）。
- 不做记忆的自动语义合并。聚类只提示，裁决必须由人点。见 `README.md:88-101`（「3. 本地聚类：只提示，不自动合并」）。
- 不把「零提醒」显示成「一切正常」。零提醒有两种相反解读，必须用计数区分。
- 不在提示词里写「请检查自己」。自检一旦只存在于提示词里就变成新的表演面，零成本。

## 5. 被数据打脸的假设

这一节比前面几节都重要，因为它记的是**没做成**的部分。

### 提醒没有改变写作行为

【事实】`README.md:302-336` 记录了一次实测：只在「本来就该触发对账档」的回答里比较——

- 前面有质检提醒的：10 / 15 = 67% 写了对账块
- 前面没有提醒的：14 / 24 = 58% 写了对账块

【事实】README 自己的结论是「差 8 个百分点，仍然落在噪声内」，且分母只有 15。写得最勤的那几条长回答（2000 字以上）前面都没有提醒。

【推断】所以提示词里的硬约束才是真起作用的那个，机器判词不是。复现命令：`node scripts/remind-effect.mjs`。

### 衰减窗口三个数是拍的

【事实】`lib/decay.mjs:30` 的注释自己写着：

> 540 / 365 / 180 三个数**没有任何数据支撑**，是我按上面的道理随手定的量级。

这条留在这里，是因为它标出了一个真实的窟窿：整套记忆机制里，唯一「像论文参数」的那三个数，其实是估的。

### 一个已经被修掉的顺序 bug

【事实】提醒额度（`MAX_REMINDERS_PER_TURN`，默认 2，`index.mjs:324`）早期被放在「取事件、跑判据」之前，后果是额度挡掉的是**检查**而不是**提醒**，那几条回答根本没被检查过。「没查」长得和「查过没事」一模一样 —— 正好是这个项目明令禁止的那件事。现在顺序是「先查，再决定要不要说」。见 `README.md:296-300`。
